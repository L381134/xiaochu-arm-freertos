0先说结论

这份程序从头到尾只做三件事，你只要记住这三句话，整份代码就通了：

① 收指令

手机 App 通过蓝牙发来一串文字，程序把它读进来、看懂。

② 算目标

根据这串文字，算出 5 根手指各自"最终应该转到多少度"。

③ 慢慢动

每 10 毫秒让手指朝目标挪一小步，直到走到为止。

注意 代码不是按从上到下的顺序执行的。上电后，程序先执行 setup()（只跑一次），然后永远在 loop() 里循环。中间那一大堆 class 段落，只是"定义图纸"，本身不会动。

1整体印象：信号是怎么一路传到手指的

整条链路有五站。代码负责中间那两站。

手机 App  ──蓝牙BLE──▶  ESP32-C3 主控  ──I2C──▶  PCA9685 驱动板  ──PWM──▶  5 个舵机  ──▶  手指
XiaochuHand.exe          （这份程序）        GPIO8/9        地址 0x40          通道 0~4
环节做什么代码里对应
手机 App把"握拳"或"1 号手指 90°"变成一串文字发出去——
蓝牙 BLE无线把这串文字送给 ESP32MyCallbacks
ESP32-C3看懂文字，算出 5 个目标角度Finger / Hand
I2C 总线ESP32 用两根线把"角度"告诉驱动板Wire.begin(8,9)
PCA9685把角度翻译成脉宽，输出 PWM 信号pwm.setPWM()
SG90 舵机按脉宽转动，带动手指——
为什么中间要加一块 PCA9685？ ESP32 自己也能输出 PWM，但它的引脚数量有限、精度不够，同时带 5 个舵机容易抖动。PCA9685 是一块"16 路 PWM 放大器"，主控只要说一句"3 号通道转到 90°"，它就自己完成所有时序细节，省心又稳定。

2读代码的正确顺序

新手最容易犯的错，是从第 1 行开始硬读。那样读到第 50 行就会迷路。请按下面这个顺序：

  1. 先看 setup()（第 218 行）这是开机流程，能看到所有硬件是怎么被"唤醒"的。它是全文最好懂的一段。
  2. 再看 loop()（第 267 行）只有两行。看完你会发现：核心动作就是一句 hand.run()。
  3. 然后看 MyCallbacks（第 189 行）这是"入口"，蓝牙来的数据从这里进来。顺着它找下去，就能找到所有分支。
  4. 最后回头看 class Finger / Hand此时你已经知道它们"被谁调用、什么时候被调用"，再看定义就不会悬空。
一句话记住 setup 是开机清单，loop 是心跳，Finger 和 Hand 是工具箱，MyCallbacks 是入口。

3五个必备概念（看懂这五个就够用了）

① #define —— 给数字起外号

#define SDA_PIN 8

意思是"以后代码里写 SDA_PIN，就等于写 8"。这样做的价值是：以后要换引脚，只改这一行，全文自动跟着改。

② 变量 —— 会变的盒子

float currentPosition;   // 小数盒子，装"当前角度"
int   channel;           // 整数盒子，装"通道号"
bool  isStill;           // 真假盒子，只能是 true / false

③ 函数 —— 打包好的一串动作

void run() {
  // 里面的代码就是"这串动作"
}

void 表示"不需要返回结果"。括号里如果写着东西（比如 int angle），那就是"做这件事需要你告诉我一个数"。

④ 类与对象 —— 图纸与实物

class Finger { ... };     // 图纸：描述"一根手指"长什么样
Finger f1(...);              // 实物：按图纸造出一个具体的手指

本程序里只有一张图纸 Finger，却造出了 5 个实物（5 根手指）。Hand 是"管理这 5 个实物"的班长。

⑤ 判断与循环 —— 程序的"岔路"和"重复"

if (条件) { ... } else { ... }        // 岔路：满足条件走 A，否则走 B
for (int i=0; i<5; i++) { ... }     // 重复：i 从 0 数到 4，执行 5 次
小技巧 for (int i=0; i<5; i++) 在这份代码里出现很多次，它每次都只有一个意思："对 5 根手指，每根都做一遍"。

下面按代码里原本的分段（作者写的那一行行 // ---------- 标题 ----------）逐个讲。

4.1 引入工具库（第 6~11 行）

#include <BLEDevice.h>                  // 蓝牙基础功能
#include <BLEUtils.h>                   // 蓝牙小工具
#include <BLEServer.h>                  // 让 ESP32 变成蓝牙"服务器"
#include <BLE2902.h>                    // 蓝牙描述符，给手机 App 用
#include <Wire.h>                       // I2C 两线通信

怎么理解：做饭前先把锅碗瓢盆从柜子里拿出来。#include 就是"把别人写好的功能借过来用"。这几个库不是 Arduino 自带的，需要先在库里搜索安装。

4.2 起外号：引脚、频率、编号（第 13~49 行）

#define SDA_PIN 8       // 数据线接 GPIO8
#define SCL_PIN 9       // 时钟线接 GPIO9

Adafruit_PWMServoDriver pwm = Adafruit_PWMServoDriver(0x40);
                          // 0x40 是驱动板的 I2C"门牌号"

#define SERVO_MIN_PULSE 150   // 对应 0°
#define SERVO_MAX_PULSE 500   // 对应 180°
#define SERVO_FREQ 50         // 50Hz，舵机行业标准

#define SERVICE_UUID    "89d60870-9908-..."  // 服务编号
#define WRITE_CHAR_UUID "39dea685-a63e-..."  // 可写特征编号
重点 UUID 必须和上位机 App 里写的完全一致，差一个字符，手机就搜不到设备或者连上后发不出数据。这是新手最常踩的坑。

手指编号与两端角度

#define FINGER_THUMB  0   // 拇指 = 0
#define FINGER_INDEX  1   // 食指 = 1
#define FINGER_MIDDLE 2   // 中指 = 2
#define FINGER_RING   3   // 无名指 = 3
#define FINGER_PINKY  4   // 小指 = 4

#define THUMB_MAX_OPEN   30    // 拇指：张开 30°
#define THUMB_MAX_CLOSED 180   // 拇指：握紧 180°
#define MIDDLE_MAX_OPEN  180   // 中指：张开 180° ← 反过来了
#define MIDDLE_MAX_CLOSED 0    // 中指：握紧 0°
为什么数字是反的？因为 5 个舵机装到机械结构上时，安装方向不一样。有的"转到 0°"是张开，有的"转到 180°"才是张开。
作者没有在代码里到处写 if 判断，而是把每根手指的两个端点做成数据写在这里，后面统一处理 —— 这是很值得学的写法。
#define DEFAULT_STEP 2.0f   // 每小步走 2°

这个是"速度旋钮"。数字越大动得越快，越小越柔和。作者原本用 1.0，注释掉改成 2.0 并在后面写了"速度翻倍"。

4.3 Finger 类 —— 一根手指（第 51~92 行）

这是全文最核心的 40 行。它管三件事：记住目标、慢慢靠近、换算成信号发出去。

属性（资料卡）

int channel;              // 接在驱动板哪个通道 0~15
int maxOpen, maxClosed;   // 张开角度、握紧角度
int direction;            // 1 = 正常，-1 = 反装
float currentPosition;    // 【当前】实际在哪
float target;             // 【目标】想去哪里
float step;               // 每小步走多少度
关键理解 currentPosition 和 target 是两个不同的东西。指令只会改 target，永远不会直接改 currentPosition。正因为这样分开，手指才能"慢慢"过去，而不是瞬间跳过去。

构造函数 —— 造手指时自动执行

Finger(int ch, int open, int closed, int dir)
  : channel(ch), maxOpen(open), maxClosed(closed), direction(dir) {
  currentPosition = (direction == 1) ? maxOpen : maxClosed;
  target = currentPosition;   // 目标 = 当前位置 → 开机先不动
  step = DEFAULT_STEP;
}

冒号后面那一长串叫"初始化列表"，作用是把括号里传进来的参数，直接存进自己的属性里。

★ 核心换算一：百分比 → 角度

void setTargetNormalized(int normalizedPos) {
  if (direction == 1) {
    target = map(normalizedPos, 0, 100, maxOpen, maxClosed);
  } else {
    target = map(normalizedPos, 0, 100, maxClosed, maxOpen);
  }
  target = constrain(target, 0, 180);
}
这是全套代码最聪明的设计。外部只需要给一个 0~100 的"握紧程度"：
  • 0 = 完全张开   • 100 = 完全握紧
至于这根手指的舵机是正装还是反装、张开角是 0° 还是 180°，全部由这一个函数内部消化掉。
结果就是：写手势的时候，所有手指都用同一套 0/100 语言，不用考虑机械差异。

★ 核心换算二：角度 → 脉宽（run 函数，第 78~88 行）

void run() {
  if (abs(currentPosition - target) <= step) {
    currentPosition = target;          // 很近了，直接对齐，防止抖动
  } else if (currentPosition < target) {
    currentPosition += step;           // 还没到，往大走一步
  } else {
    currentPosition -= step;           // 过头了，往小退一步
  }

  int pulse = map(currentPosition, 0, 180, SERVO_MIN_PULSE, SERVO_MAX_PULSE);
  pwm.setPWM(channel, 0, pulse);      // 真正把信号发出去
}
逐句拆解：
① abs() = 取绝对值，算出"离目标还差多远"。
② 如果差得比一步（step）还小，就直接对齐 —— 这一步很重要，否则手指会在目标附近来回抖动。
③ 否则就加一步或减一步，一次只挪一点点。
④ map() 做换算：把 0~180 的角度，等比映射成 150~500 的脉宽数字。比如 90° 会算成约 325。
⑤ setPWM() 是唯一真正让舵机动的语句。整份代码里，只有这一行能让舵机转。
再强调一次 run() 本身不知道"什么时候该动"。它只是"走一小步"。谁在不停地叫它走？——是 loop()。这就是"平滑移动"的全部秘密。

4.4 Hand 类 —— 一整只手（第 95~111 行）

class Hand {
public:
  Finger* fingers[5];        // 5 个格子的数组，每格放一根手指

  Hand() {
    fingers[0] = new Finger(FINGER_THUMB,  THUMB_MAX_OPEN,  THUMB_MAX_CLOSED,  1);
    fingers[1] = new Finger(FINGER_INDEX,  INDEX_MAX_OPEN,  INDEX_MAX_CLOSED,  1);
    fingers[2] = new Finger(FINGER_MIDDLE, MIDDLE_MAX_OPEN, MIDDLE_MAX_CLOSED, -1);
    fingers[3] = new Finger(FINGER_RING,   RING_MAX_OPEN,   RING_MAX_CLOSED,   1);
    fingers[4] = new Finger(FINGER_PINKY,  PINKY_MAX_OPEN,  PINKY_MAX_CLOSED,  -1);
  }

  void moveToNormalized(int pos) { // 5 根一起动
    for (int i=0; i<5; i++) fingers[i]->setTargetNormalized(pos);
  }
  void run() { // 5 根各走一小步
    for (int i=0; i<5; i++) fingers[i]->run();
  }
};
Hand 自己几乎不干活，它是个"班长"。你叫班长"全体握拳"，班长就挨个通知 5 个组员。
看最后那个 1 / -1：中指和小指是 -1，说明这两个舵机是反装的。
注意 fingers[i]->run() 里的箭头 ->：意思是"让第 i 号手指去执行 run()"。因为 fingers 里存的是手指的"地址"，不是手指本身。

4.5 HandMovementFactory —— 手势菜单（第 114~183 行）

这个类就是一张菜单。你报一个名字，它把 5 根手指的目标值摆好。规律非常好找：

if (name == "fist") {
  hand->moveToNormalized(100);              // 握拳：全体 100
} else if (name == "one") {
  hand->fingers[0]->setTargetNormalized(100);   // 拇指  握紧
  hand->fingers[1]->setTargetNormalized(0);     // 食指  张开 ← 只有它伸出来
  hand->fingers[2]->setTargetNormalized(100);   // 中指  握紧
  hand->fingers[3]->setTargetNormalized(100);   // 无名指 握紧
  hand->fingers[4]->setTargetNormalized(100);   // 小指  握紧
}
重要 这些函数只是在"设定目标"，不会立刻让手指动。真正的运动发生在 loop() 里。所以你点一下"握拳"，手指是缓缓握住，不是瞬间缩起来。

最后那个 else 分支：如果名字一个都对不上，就在串口打一行提示，方便你发现"是不是打字打错了"。

4.6 MyCallbacks —— 蓝牙收信员（第 189~215 行）

这是整份代码的"入口"。每当手机往蓝牙特征里写数据，onWrite() 就会被自动调用（不是我们主动去调的）。

void onWrite(BLECharacteristic* pCharacteristic) override {
  String value = pCharacteristic->getValue();   // 1. 读出来
  if (value.length() == 0) return;             //    空消息，忽略
  String cmd = value;
  cmd.trim();                                   //    去掉首尾空格换行

  Serial.print("Received: ");                   // 2. 打印出来方便调试
  Serial.println(cmd);

  if (cmd.startsWith("servo_")) {                // 3. 判断格式
    int eqPos = cmd.indexOf('=');              //    找等号位置
    if (eqPos != -1) {
      String idxStr = cmd.substring(6, eqPos);    //    切出 "1"
      int finger = idxStr.toInt();               //    变成数字 1
      if (finger >= 0 && finger < 5) {           //    编号必须合法
        String angleStr = cmd.substring(eqPos + 1);
        int angle = angleStr.toInt();            //    切出 "90"
        hand.moveFingerAngle(finger, angle);    //    设定目标角度
      }
    }
    return;                                        //    处理完就结束
  }

  HandMovementFactory::applyGesture(&hand, cmd);  // 4. 否则当成手势名
}

字符串 "servo_1=90" 是怎么被切开的？

字符位置servo_1=90
下标0123456789

indexOf('=') 找到 7。于是 substring(6, 7) 切出 "1"（手指编号），substring(8) 切出 "90"（角度）。注意下标是从 0 开始数的，这是编程里的通用规矩。

调试技巧 如果你的机械手不听话，打开 Arduino IDE 的"串口监视器"（速度选 115200），就能看到每一句 Received: xxx。这样一眼就知道是"指令没收到"还是"收到了但没看懂"。

4.7 setup() —— 开机清单（第 218~264 行）

上电后只执行一次。分成 5 步，非常好读：

  1. 开串口（115200）为了能用电脑看日志。串口监视器里波特率必须也选 115200，否则全是乱码。
  2. 启动 I2C 并初始化驱动板Wire.begin(8, 9) 指定引脚；pwm.begin() 唤醒板子；setOscillatorFrequency(27000000) 告诉它晶振是 27MHz，否则频率会算错。
  3. 自检：驱动板接好了吗给地址 0x40 发一个空消息，返回 0 表示对方应答了。如果没应答就打印错误并 while(1) 卡死 —— 这是故意的，硬件不通后面做啥都白费。
  4. 让所有手指回到"张开"先设目标，再直接输出一次信号。这是为安全：防止上电瞬间手指突然攥紧夹到东西。
  5. 打开蓝牙，开始广播设备名 xiaochu，手机上搜到的就是它。挂上收信员 MyCallbacks，然后 pAdvertising->start() 让手机能发现。
Wire.beginTransmission(0x40);
if (Wire.endTransmission() == 0) {
  Serial.println("PCA9685 found at 0x40");
} else {
  Serial.println("ERROR: PCA9685 not found!");
  while (1);        // 停在这里，不再往下走
}
看到这行说明什么 如果串口一直显示 ERROR: PCA9685 not found!，那就是硬件问题，不是代码问题。按顺序查：
① SDA/SCL 是否接反（GPIO8 / GPIO9）② 驱动板 VCC 是否接了 3.3V ③ GND 是否共地 ④ OE 是否接了 GND。

4.8 loop() —— 心跳（第 267~270 行）

void loop() {
  hand.run();      // 5 根手指各朝自己的目标挪一小步
  delay(10);       // 停 10ms 再进下一轮
}

只有两行，但它是"手指能动起来"的根本原因。程序会以约每秒 100 次的速度重复这两行，所以：

step 值走完 100° 需要手感
2.0（当前）约 0.5 秒利落，稍快
1.0（原来）约 1 秒平稳自然
0.3约 3.3 秒很慢很柔，像科幻片

5三个核心机制，再串一遍

机制一：两套坐标系（0~100 和 0~180）

写手势的人只面对：  0 ~ 100      （0=张开，100=握紧）
                      ↓  setTargetNormalized() 内部自动转换
代码内部处理的是：  0° ~ 180°     （舵机真实角度）
                      ↓  run() 里再转换一次
驱动板需要的是：   150 ~ 500     （脉宽数字）

每一层只关心自己那一层。这就是"分层"的好处：要加手势，你只管写 0/100；要换舵机，你只管调脉宽范围。互不影响。

机制二：map() 等比换算

map(要被换算的值, 原来范围最小, 原来范围最大, 新范围最小, 新范围最大)

假设要把 90° 换算成脉宽（范围 150~500）：

90° 在 0~180 里的位置 = 90/180 = 50%
50% 落在 150~500 里 = 150 + 0.5 × (500−150) = 325

代码里 map() 自动帮你算完了。如果反过来写 map(v, 0, 100, maxClosed, maxOpen)，就是"把范围倒过来映射"，用于处理反装的舵机。

机制三：只改目标，不改当前值

收到指令 → 只改 target
loop()   → 让 currentPosition 一点点靠近 target

如果把这两件事混在一起（收到就立刻设位置），舵机会"唰"地甩过去，既吵又伤齿轮，还容易把机械结构撞坏。分开之后，才能实现平滑运动。这个思路在机器人、动画、游戏里到处都在用，叫"缓动 / 插值"。
